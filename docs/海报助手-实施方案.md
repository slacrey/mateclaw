# 海报助手 Agent 实施方案

> 目标:在 mateclaw 中新建一个「海报助手」数字员工,支持**对话生成海报 →（点击生成的图片）进入编辑页面 → 分层 + 蒙版局部重绘 → 多轮迭代**。
>
> 本方案基于对 5 个方向的代码/论文/工业级调研(Jaaz、vue-fabric-editor、NanoBananaEditor、next-ai-draw-io、mateclaw 现有代码、CreatiPoster/COLE/Paper2Poster 论文、Canva/Firefly/GPT-4o 工业实践)综合得出。
>
> 调研日期:2026-06-04

---

## 0. 核心结论(TL;DR)

1. **mateclaw 已具备约 70% 地基**:生图工具(`image_generate`,已是系统级工具)、provider 层(DashScope/Qwen-Image-Edit 已接入且支持 IMAGE_EDIT)、agent 框架(StateGraph + 模板机制)、文件存储与 serving、SSE 异步回推、对话图片渲染。**真正要新建的只有两块**:① 前端的「分层 + 蒙版」编辑页;② 后端的「编辑会话 + 版本 + 蒙版透传」逻辑。

2. **没有 turnkey 开源项目可直接 fork**。开源里「对话生成可编辑海报 + 中文 + 多轮编辑」三者兼得的为零。最佳实践是**自己组装**,但每一层都有明确的可借鉴对象。

3. **前端编辑器选定 `vue-fabric-editor` 的 `@kuaitu/core`**(MIT、Vue3 原生、框架无关 SDK)。蒙版交互需自建一个插件(约 1–2 人日),抄 NanoBananaEditor 的「离屏 canvas 按原图像素生成二值 mask」对齐法 + Firefly 的「选区→新非破坏图层→变体→羽化回填」时序。

4. **建议分阶段交付**:
   - **阶段一(MVP)**:对话生位图海报 → 点击进编辑页 → 蒙版局部重绘(Qwen-Image-Edit)→ 版本历史。**直接满足用户本次的明确需求**,全部基于已有能力。
   - **阶段二**:引入「设计 JSON 协议」,LLM 产出可编辑分层版式,前景矢量 + 背景扩散解耦,实现真正的「对话生成可编辑海报」。
   - **阶段三**:视觉在环自校正、多尺寸 re-layout、品牌一致性。

## 1. 总体架构

业界与论文已高度收敛到「**设计 JSON 作为单一事实源**」的五层架构(来源:CreatiPoster / COLE / Paper2Poster / Canva / Firefly):

```
L1 意图理解      对话 → 结构化需求(主题/文案/品牌/尺寸/风格)
L2 版式规划      LLM 产出"画布 + 有序图层数组 + 背景prompt"的设计JSON   ★单一事实源★
L3 渲染          前景:矢量/对象确定性渲染(文字保持可编辑) + 背景:条件扩散生成
L4 可编辑画布    设计JSON ⇄ 画布对象双向绑定;"点图进编辑页"=加载该图的设计JSON
L5 蒙版迭代      选区→prompt→生成到带mask的新非破坏图层→变体→羽化回填(Firefly范式)
```

**关键决策:务实分阶段。** 完整的 L2 设计 JSON(CreatiPoster 式 protocol model)是北极星,但需要接入/训练版式生成模型,工作量大。因此:

- **阶段一直接做 L4 + L5 的"位图版"**:海报本体是一张位图(由 Qwen-Image-Edit 生成),编辑页负责「在位图上叠加可编辑文字/素材图层 + 蒙版局部重绘」。"点击图片进编辑页"在此阶段 = 用该位图初始化 fabric 画布。
- **阶段二补齐 L2 + L3**:让 LLM 输出设计 JSON,前景分层渲染,背景单独生成,设计 JSON 成为画布的事实源。

> 这样阶段一就能交付用户要的「海报助手 + 点击进编辑页 + 蒙版改图」,且不赌任何未验证的重型能力。

## 3. 数据模型设计

### 3.1 后端表(Flyway V134,h2 + mysql 双份)

**`mate_poster_session`**(编辑会话 = 一张海报的完整编辑生命周期):

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | 雪花 ID |
| `workspace_id` | BIGINT | 工作区 |
| `agent_id` | BIGINT | 海报助手 agent |
| `conversation_id` | VARCHAR | 关联对话(可空,编辑页也可脱离对话) |

| `current_version_id` | BIGINT | 当前选中版本 |
| `design_json` | CLOB/LONGTEXT | 阶段二:设计 JSON 事实源(阶段一可空) |
| `status` | VARCHAR | draft/active/archived |
| `create_time`/`update_time`/`deleted` | | 标准列 |

**`mate_poster_version`**(版本节点 = 一次生成或一次编辑,构成可分支树):

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | 雪花 ID = EditNode.id |
| `session_id` | BIGINT | 所属会话 |
| `parent_id` | BIGINT NULL | **父版本(指向任意版本,null=根)**——支持真分支 |
| `kind` | VARCHAR | generate / edit_mask / edit_text / regenerate |

| `edit_mode` | VARCHAR | inpaint / regenerate / outpaint |
| `base_image_uri` | VARCHAR | 本轮底图(edit 时=父版本输出) |
| `mask_image_uri` | VARCHAR NULL | 本轮蒙版(二值 PNG) |
| `output_image_uri` | VARCHAR | 本轮输出图(serving URL/相对路径) |
| `canvas_json` | CLOB/LONGTEXT | 该版本的 fabric 画布工程(可再编辑) |
| `params_json` | CLOB | seed/model/strength 等 |
| `create_time`/`deleted` | | 标准列 |

> 存储复用现有 `data/chat-uploads/{conversationId}/`(零改动复用 `ImageFileDownloader` 下载/serving);URI 字段存 serving URL 或相对路径。

### 3.2 设计 JSON Schema(阶段二的 L2 输出契约)

综合 CreatiPoster §3.1.2 + Crello schema + COLE。坐标**归一化 [0,1]** 以支持多尺寸 re-layout;数组顺序 = z-order;每层有稳定 `id` + `locked`(支撑"锁定部分、只重生其余")。

```jsonc
{
  "schema_version": "1.0",
  "canvas": { "width": 1080, "height": 1920, "unit": "normalized", "dpi": 72 },
  "background": {
    "prompt": "soft gradient studio backdrop, warm light",
    "image_ref": "bg_v3.png",       // null=尚未生成
    "seed": 12345, "model": "qwen-image"
  },
  "layers": [                         // 顺序 = z-order(底→顶)
    {
      "id": "txt_title",              // 稳定 ID(多轮编辑/锁定锚点)
      "type": "text",                 // text / asset / shape
      "locked": false,                // true=本轮 AI 不许改
      "bbox": { "left": 0.08, "top": 0.62, "width": 0.84, "height": 0.12 },
      "rotation": 0.0, "opacity": 1.0,
      "content": "限时五折",
      "style": {
        "font_family": "Source Han Sans", "font_size": 96, "font_weight": "bold",
        "color": "#1A1A1A", "align": "center", "line_height": 1.2,
        "letter_spacing": 0.02, "stroke": { "color": "#FFFFFF", "width": 2 }
      },
      "editable_as_text": true        // true=live text;false=已栅格/转曲
    },
    {
      "id": "asset_product", "type": "asset", "locked": true,
      "bbox": { "left": 0.25, "top": 0.10, "width": 0.50, "height": 0.45 },
      "rotation": 0.0, "opacity": 1.0,
      "src": "uploads/shoe.png", "mask_type": "alpha", "fit": "contain"
    }
  ]
}
```

### 3.3 前端运行时模型(EditNode 树,改进 NanoBanana)

```
Project { id, title, canvas{w,h}, rootNodeId, currentNodeId, nodes: EditNode[] }

EditNode {                       // 统一"一次生成或编辑",对应 mate_poster_version
  id, parentId|null,             // ★指向任意节点(修复 NanoBanana 断链)
  kind: 'generate'|'edit_mask'|'edit_text',
  prompt, params{seed,model,strength},
  inputs: { baseAssetId?, maskAssetId?, referenceAssetIds? },
  outputAssetIds: string[], selectedOutputIndex,
  canvasJson                     // 该版本 fabric 工程
}

Asset { id, role:'source'|'mask'|'output'|'mask_overlay',
        storageRef,              // ★存对象存储/URL,不存 base64(修复内存丢失)
        mime, width, height, sha256 }

MaskData { id, nodeId,
           strokes: BrushStroke[],     // ★矢量笔迹(可撤销/可重放),非只存PNG
           renderedMaskAssetId, bounds{x,y,w,h}, feather }
```

**相比 NanoBanana 的三处改进(都是它的实测坑)**:
1. `parentId` 指向任意节点 → 真·多轮 + 可分支(NanoBanana 的 Edit 只能挂 Generation,断链)。
2. 资产本体进存储、节点只存引用 → 解决它"base64 塞内存、刷新即丢"(其 IndexedDB 持久层定义了却从未被调用)。
3. 蒙版存矢量 strokes → 支持撤销最后一笔 / 二次微调(NanoBanana 无真 undo,README 夸大)。

3. **导出二值 mask**(核心):建与 workspace 等尺寸的离屏 `HTMLCanvasElement`(抄 `WaterMarkPlugin.createCanvas` 范式),黑底白笔迹画 strokes → `toDataURL('image/png')`。**唯一要仔细测的是 zoom/viewportTransform/workspace 偏移下 base 与 mask 的像素对齐**(参考 `MaskPlugin.setCoverMask` L77、`WorkspacePlugin.setZoomAuto` L169 的换算)。
4. **结果贴回**:后端返回重绘图 → `fabric.Image.fromURL(...)` + `editor.addBaseType(img)` 叠成**新图层**(非破坏),或对原图 `setSrc`。
- 撤销/重做:`HistoryPlugin` 自动入栈,Ctrl+Z 即生效。

> 工作量:核心插件约 150–250 行,1–2 人日。难点不在 fabric 能力(都具备),在像素对齐。

## 6. 端到端时序(阶段一 MVP)

```
① 对话生成
   用户对海报助手说"做一张五折促销海报,暖色调"
   → StateGraph agent(planner 定版式 → 调 image_generate)
   → ImageGenerationService → DashScopeImageProvider(Qwen-Image)出图
   → 落 data/chat-uploads/{conv}/ → 广播 async_task_completed
   → MessageBubble 渲染 <img>(L291-296)

② 点击进编辑页
   用户点图上的"编辑" → POST /api/v1/posters 建会话(root version=该图)
   → router.push('/poster-editor/{sessionId}')
   → PosterEditor 用 fetchAuthenticatedBlob 加载原图 → fabric 画布初始化

③ 蒙版局部重绘(Firefly 时序)
   用户涂抹"要改的区域" → InpaintMaskPlugin 采集矢量 strokes
   → 提交:离屏 canvas 按原图像素生成二值 mask PNG(白=改/黑=留)
   → 调 image_generate(action=generate, sessionId, editMode=inpaint,
                       image=当前图, maskImage=mask, prompt=用户指令)
   → DashScope 返回结果(可多变体)→ 落盘 → appendVersion 写 mate_poster_version
   → 前端把结果作为新图层贴回画布(非破坏)+ 客户端羽化回填(选区外像素保持)

④ 多轮迭代 / 版本
   再次涂抹提交 → 以上一版输出为 base → 新 version 挂当前节点(可分支)
   版本面板:取各 version 的 output 并排,点选切换 current_version
   文字修改:用户直接在画布加/改可编辑文字图层(live text,不烧进位图)

⑤ 保存/导出
   editor.getJson() 存 canvas_json(可再编辑) + editor.preview() 出成品 PNG
   → POST /api/v1/posters/{id}/versions 或 chatApi.uploadFile 落盘
```

## 8. 风险与坑(汇总)

| 风险 | 说明 | 对策 |
|---|---|---|
| **DashScope mask 静默丢弃** | provider payload + 模型 spec `supports` 白名单 + request 字段,三处缺一,mask 被 `PayloadBuilder` 静默过滤 | §4.D 三处同改;加单测验证 mask 进了 payload |
| **mask 像素对齐** | zoom/viewportTransform/workspace 偏移下,base 与 mask 不对齐 → 重绘错位 | 离屏 canvas 用原图真实像素;复用 `MaskPlugin.setCoverMask` 换算;重点测 |
| **软蒙版整图重建** | Qwen/Gemini/gpt-image-1 的 mask 多是"软引导+整图重生",选区外不保证逐像素不变 | **客户端显式回填**:`out=orig*(1-feather)+gen*feather`,把"选区外不变"握在自己手里 |
| **文字烧进位图** | 改一个字要整图重生(GPT-4o 痛点) | 文字默认 live 可编辑图层,JSON 始终保留文字对象,导出再决定转曲 |
| **Flyway 双份** | h2 与 mysql 必须同步,否则一端 schema 漂移 | V134 两份同时提交 |
| **受保护文件鉴权** | serving URL 带 JWT,裸 `<img src>` 会 401 | 统一 `fetchAuthenticatedBlob` |
| **vue-fabric-editor 跨界引用** | `packages/core` 的 `SimpleClipImagePlugin` 引用了 `src/utils/math` | 拷 `math.ts` 过去,或不用该插件 |
| **AGPL 污染** | NanoBananaEditor 是 AGPL-3.0 | 只学设计/数据流,**不抄代码**;自研实现 |
| **ArchUnit 约束** | 新 `ToolCallback` 须 override `call(String,ToolContext)` | 本需求扩 `@Tool` bean(`ImageGenerateTool`)不受此约束;若新增 callback 注意 |
| **NanoBanana 三坑** | Edit 断链 / base64 内存丢失 / 无真 undo | §3.3 已用 EditNode 树 + storageRef + 矢量 strokes 规避 |
