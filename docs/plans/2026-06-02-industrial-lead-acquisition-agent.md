# 工业级「抖音评论获客」Agent — 路线图执行计划(v1 → v4)

> 日期:2026-06-02 · 基线分支:`feat/browser-phase-3.1-direct-wss`
> 本版按**用户产品路线图 v1→v4** 组织。修正:**不要确认卡**;**v1 含真实"发送私信"**(现差这最后一步);**每个版本动工前先调研当前实现 + 行业最佳实践**。
> 质量优先级仍是 **稳定 > 易用 > 可观测**,作为**贯穿每版**的横切轨道(不堆到最后,也不在 v1 过度重构)。

---

## 0. 产品路线图(用户定义)

| 版本 | 目标 | 关键点 |
|---|---|---|
| **v1** | 固定链路端到端跑通 | 打开抖音→搜 openclaw→筛选→最多点赞→开第一个视频→开评论区→读评论→开第一条评论用户主页→关注→打开私信入口→**发送私信**。现状**只差最后一步(发送)**。 |
| **v2** | 快捷入口"抖音截客" + 结构化输入 | 点快捷入口 → 填:**搜索主题 / 匹配评论 / 发送的私信 / 评论内容 / 排序方式 / 拉取视频数量** → 跑参数化任务 |
| **v3** | 截客模板 | 把 v2 输入存为命名模板;下次点模板**一键复用直接发** |
| **v4** | 数据可视化 | 执行时长 / 主题 / 匹配评论 / 总视频数 / 总关注数 / 总私信数 |

## 1. 实现铁律:先看现状,再对标行业(每版动工前必做)

> 用户要求:"技术实现的时候需要先看当前项目的实现 及行业最佳实现"。

**可复用的既有积木**(动工前逐一读、能复用就复用,不重造):
- 动作原语:`ExtensionBrowserTool`(navigate/observe/click/type/scroll/hover/press_key/click_at)+ grounding 级联(DOM→A11y→Vision/SoM)。
- 现有链路:`LeadBrowserHarnessTool`(搜索/筛选/排序/开视频/开评论已通;新增"全量采集评论 + 自动下一个视频";已到"打开私信入口",差"发送")。
- 传输:offscreen-WS(socket 扛 SW 挂起,断线根因已修)。

**每版第一步**固定为"现状调研 spike":读相关模块现状 + 查行业最佳(RPA/Web 自动化/Agent 可靠性/可观测),产出取舍说明,再动手。

## 2. 横切质量轨道(每版都带一点)

- **稳定(#1)**:verify-by-effect(看到预期后置态才算成功)、有界退避重试、**幂等**(已关注不重关、私信已发不重发)、失败分类法;**v2 起**状态机 + 检查点续跑 + LAYOUT_DRIFT 熔断。
- **可观测(#3,但前置)**:**v1 起**就落最小 `RunRecord`(供 v4 直接聚合);逐步加 `StepEvent`、端到端 trace、指标 + 视觉成本、失败截图。*(看不见就修不动,所以最小集前置。)*
- **易用(#2)**:**去确认卡**;v2 起结构化输入 + 进度/取消;v4 看板。
- **安全(最后)**:外联(关注/私信/发送)走 Tool Guard;pacing/配额留到安全阶段。

## 3. 各版本计划

### v1 — 固定链路跑成"稳定可复跑":全量采集 + 多视频 + 发送私信
**v1 完整范围**(用户澄清后):搜索→筛选→最多点赞→**逐个视频**→打开评论区→**滚动采集全部评论(去重)**→**自动进入下一个视频**→(对命中评论)开主页→关注→打开私信→**发送私信**。

**进度(2026-06-02)**
- ✅ 搜索 / 筛选 / 最多点赞排序(`lead_browser_douyin_*`)。
- ✅ 打开视频 + 打开评论区:评论入口改为「**树触发 → 视觉兜底 → X 快捷键末位**」,修掉死板的 X-first;视觉用 `qwen3-vl-plus`(实测可返回坐标)。
- ✅ **全量采集评论 + 自动下一个视频**:新工具 `lead_browser_douyin_collect_comments_across_videos(query, maxVideos)` —— 滚动评论区到底(四种停止:到底标记 / 连续 2 次无新 / 单视频上限 300 / 滚动上限 40)+ 文本去重;"下一个"用重搜+重排回到排序结果页、按点赞挑未处理视频;中途失败保留已采集。**已部署 restart-21,待真机验。**
- ✅ 底座修复:offscreen-WS(断线根因)、CDP 截图 HiDPI、视觉 provider 自动选择修复、WS 8MB。
- ⏳ **发送私信**(v1 最后一步,未做):私信框 grounding(textbox / 名"发消息·私信" + 视觉兜底)→ `type` 文案 → 点"发送";**verify-by-effect**:观察到文案进入会话消息流才算成功。
- ⏳ 硬化:verify-by-effect 全链 + 有界重试 + **幂等**(已关注跳过、同一用户私信已发不重发)+ 失败分类(登录/风控/无结果/布局漂移/断线)。
- ⏳ **最小 RunRecord**:记 run_id、主题、命中评论、关注/私信结果、时长、各视频采集数 —— v4 直接用。
- ⏳ 安全:发送/关注经 `BROWSER_OUTBOUND_CONTACT_CLICK`(默认可配:逐条审批 / 直发)。

**待真机确认的关键点**:评论区滚动是否真加载更多(看 `stop_reason` + `comment_count`,若只有几条=滚动没作用到面板,改面板内坐标滚动);多视频是否真换(看 `videos_processed` + 标题不重复)。

**已知欠账(诚实)**:`collect_comments_across_videos` 暂无专门单测(真实滚动/换视频序列离线测不出,待真机确认序列后补回归测试,避免写"猜的假绿测试")。

**验收**:真机冒烟(你验)——前 3 个视频各自全量采集、自动连跑;通过后补"发送私信"最后一步 + 回归测试。

### v2 — 快捷入口 + 结构化输入(此时拆单体,转 spec 驱动)
**入口**:管理端/侧栏一个"**抖音截客**"快捷卡 = **发起入口**(非确认卡,填完即跑)。
**输入(6 项)**:搜索主题、匹配评论(关键词/语义)、发送的私信、**评论内容**(见 §5 待确认)、排序方式、拉取视频数量。
**架构转折(关键)**:参数任意化 + 后续模板化会让"硬编码单体"撑不住 →**在此把单体拆为**:
- 通用原语(动作层,已有)+ **平台适配器** `CommentLeadSteps(douyin)`(提供 grounding 提示/语义判定,换平台只换它)+ **状态机编排器**(`SEARCH→SORT→PICK_VIDEO→OPEN_COMMENTS→READ→MATCH→OPEN_PROFILE→FOLLOW→COMMENT?→OPEN_DM→SEND`)。
- 每步 `Step{前置, 动作, 后置验证, 重试, 幂等键}`;`RunRecord` 每步落检查点 → 断线续跑。
- 落实你既定方向"通用原语优先、去 harness 短路"(#121)。
**先调研**:读 `workflow/` 引擎能否直接承载(step 模式/表达式),决定"复用 workflow DSL"还是"轻量状态机";读 draftgen 能否把自然语言转 spec。
**验收**:表单跑参数化任务(不同主题/排序/数量);注入断线→续跑;参数边界(数量上限)生效。

### v3 — 抖音截客模板(存 / 复用)
- 把 v2 的输入持久化为**命名模板**(新表 `mate_lead_template` + Flyway h2/mysql 双份)。
- 点模板 → 直接以该 spec 发起(复用 v2 编排器)。
- 易用:模板增删改查、改名、收藏。
**先调研**:看现有"模板/预设"类表与 UI 模式(如 workflow 模板),沿用同款 CRUD + 前端组件。
**验收**:存模板→改名→一键发起跑通。

### v4 — 数据可视化
- 基于 **v1 起累积的 RunRecord + StepEvent** 聚合:执行时长、主题、匹配评论数、总视频数、总关注数、总私信数(+ 趋势/历史)。
- 面板:Runtime Console 新增"截客运行"视图(任务列表 → 单任务下钻 → 汇总卡 + 时间线 + 失败截图)。
- 顺带:视觉/LLM 成本/任务(呼应费用关切)。
**先调研**:看 Runtime/Doctor 现有图表与数据接口,沿用同款聚合 + 图表组件。
**验收**:跑数次 → 看板各项指标正确。

---

## 4. 为什么这个顺序成立(避免过度工程)
- **v1 不重构**,只补"发送"这最后一步 + 把现链路硬化到可复跑 + 落最小 RunRecord。最快交付可演示价值。
- **v2 才拆单体**:只有当"参数任意化 + 模板化"真正到来,硬编码单体的代价才暴露,此时拆收益最大,也正好落实"通用原语优先"。
- **v3 复用 v2 的 spec**(模板=存一份 spec)。
- **v4 复用 v1 起就在记的 RunRecord**(所以可观测最小集必须 v1 就埋)。
- 每版可独立验收、可上线;质量轨道按版递进,不堆到最后。

## 5. 待确认/默认假设(我按默认推进,你可纠正)
1. **"评论内容"(v2 输入)**:理解为 **agent 要发表的评论**(新增"发表评论"动作,故状态机含 `COMMENT?`)。若只是"匹配用文本"则与"匹配评论"重复——默认按"发表评论"设计。
2. **发送私信(v1)= 真实外联**:默认经 `BROWSER_OUTBOUND_CONTACT_CLICK` 审批,提供"直发/逐条确认"开关(安全细化在最后,但 v1 就会真的发,需要一个默认策略)。
3. **去确认卡**已采纳:发起入口填完即跑,运行中不再弹确认;控制改为进度 + 取消/暂停。
